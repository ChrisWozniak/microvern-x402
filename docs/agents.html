For autonomous agents

Review within rules you set.

Give an agent a compact, explicit boundary once. It can then validate a transaction, verify a no-spend quote, and request a protected report without navigating the human website.

MicroVern is not a wallet. The local MCP server accepts no seed phrase or private key. Any payment proof comes from the agent’s own approved wallet, HSM, or signing service.

1. Set boundaries

Pin a network, versioned policy, transaction limits, and exact recipient allowlist.

2. Check for free

Validate the unsigned group before a payment request or signer is involved.

3. Pay only on approval

Check the exact quote against a payment cap, then use an externally approved payment proof.

The safe MCP sequence

The three tools deliberately keep payment separate from transaction review.

  1. 1
    validate_transaction
    Free structural and local boundary check. No payment, wallet, signature, or broadcast occurs.
  2. 2
    get_quote
    Returns a no-spend x402 quote only after the group, profile, recipient list, and payment cap all pass local checks.
  3. 3
    inspect_transaction
    Without a payment proof, it returns the approval-required quote. With an externally created proof, it returns the report and verifies its request binding.

Start with a conservative recipe

strict-usdc-v1recipient allowlistexplicit caps

Use for a narrowly bounded USDC payment. It blocks outgoing ALGO, rekeys, close-outs, and administrative actions.

  "serviceUrl": "https://microvern-x402-mainnet.onrender.com",
  "network": "algorand-mainnet",
  "unsignedTransactionGroup": "<base64 unsigned group>",
  "policyProfile": "strict-usdc-v1",
  "transactionLimits": { "maxAlgoSend": 0, "maxUsdcSend": 0.01 },
  "allowedRecipients": ["<approved 58-character Algorand address>"]
}

Choose the profile that matches the job

ALGO-only: use algo-only-v1 and supply a deliberate ALGO limit. No administration: use no-admin-actions-v1 when asset or application administrative changes must remain blocked. Every recipe still needs exact recipient and spend boundaries.

Required safeguards

  • Known profile: a versioned profile, not an unreviewed free-form rule.
  • Transaction caps: explicit maximum outgoing ALGO and USDC.
  • Recipient allowlist: at least one exact address the agent may consider.
  • Payment trust: pinned x402 network, USDC ASA, receiver, and atomic payment cap.
  • Separate signer: the agent’s wallet/HSM decides whether to create a payment proof.
  • Freshness: re-review a changed group; reuse an idempotency key only for the same logical inspection.
What agents must not do

Do not put a seed phrase, private key, customer transaction signature, or unrestricted payment authority into MicroVern. An allow result is decision support, not authorization to sign.
